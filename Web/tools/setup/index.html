Run ObieApp on Your Own Machine

Three ways to run ObieApp without relying on the hosted website — choose the one that fits your needs.

Run the full ObieWebApp UI (Explore, Acquire, Convolve) from a local server. The first load needs internet to cache PyScript + Pyodide (~50 MB) — after that the browser serves everything from its own cache and no internet is needed.

This is the simplest option. Chrome's cache is persistent across restarts; it only disappears if you manually clear browser data.

1
Get the code
One-time

Clone the repository (or download the ZIP — see the Desktop section for details):

git clone https://github.com/chrisbuerginrogers/ObieApp.git
2
Start the local server
Every session

ObieApp needs a server that sets the right security headers for SharedArrayBuffer (required by PyScript). A ready-made server script is included:

cd ObieApp/Web
python3 serve.py
cd ObieApp\Web
python serve.py
cd ObieApp/Web
python3 serve.py

You'll see: → http://localhost:8000

To use a different port: python3 serve.py 9000
3
Load the page in Chrome (internet required once)
One-time per machine

Open Chrome or Edge and go to:

http://localhost:8000

The first time you open any tool, Chrome downloads PyScript and Pyodide (~50 MB) and caches them. This is a one-time step per machine.

Why Chrome or Edge? Safari and Firefox don't support the File System Access API needed for the Data Folder feature.
4
Go offline
After first load

Disconnect, run serve.py, open localhost:8000 — everything works from Chrome's cache. The cache survives browser restarts.

If you clear browser data or switch Chrome profiles, one more online load is needed to repopulate the cache.

✓ Full web UI, fully local

All tools, Data Folder integration, templates, and exports work exactly the same as the hosted site. Your data never leaves your machine.

To update: git pull inside ObieApp/, then restart serve.py.

Download every dependency — PyScript, Pyodide, numpy, scipy, Plotly — into the repo folder once while you have internet. After that, serve.py works with no internet at all, even on machines that have never been online.

Use this if you can't rely on Chrome's cache staying intact, or if you need to copy ObieApp to an air-gapped machine.

1
Get the code and install Python
One-time

Same as the other approaches — clone the repo and make sure Python 3 is installed:

git clone https://github.com/chrisbuerginrogers/ObieApp.git

Install Python if needed: brew install python or download from python.org.

Install Python if needed — download from python.org and check "Add Python to PATH".

Install Python if needed: sudo apt install python3 python3-pip

2
Run the download script (while online)
One-time · ~50–80 MB

From the Web/ directory, run:

cd ObieApp/Web
python3 download-offline.py
cd ObieApp\Web
python download-offline.py
cd ObieApp/Web
python3 download-offline.py

The script prints its progress as it downloads each file. When it finishes you'll see a summary like:

vendor/  total: 63 MB  (12 files patched)

All set! To use ObieWebApp with no internet:
    python3 serve.py
    → http://localhost:8000  (Chrome or Edge)

What it downloads to Web/vendor/:

  • PyScript runtime (core.js, core.css)
  • Pyodide runtime (pyodide.js, pyodide.asm.wasm, …)
  • numpy + scipy wheels and their dependencies
  • Plotly (plotly-2.32.0.min.js)

It also patches all index.html and pyscript.toml files to use vendor/ paths instead of CDN URLs, and replaces the GitHub raw-file URLs with local repo paths.

3
Start the server — no internet needed from here
Every session 
cd ObieApp/Web
python3 serve.py
cd ObieApp\Web
python serve.py
cd ObieApp/Web
python3 serve.py

Open Chrome or Edge at http://localhost:8000. All assets are served locally — network cable can be unplugged.

4
Transferring to an air-gapped machine
Optional

After step 2, copy the entire ObieApp/ folder to the target machine — USB drive, network share, or any other method. The vendor/ folder and patched files travel with it.

On the target machine, install Python 3 (only Python itself needs to come from outside — no pip packages required), then run serve.py as above.

Chrome or Edge must be installed on the target machine. They don't need internet access once launched — only the URL bar needs to point to localhost:8000.
5
Going back to CDN mode
Optional

If you want to revert all patches (e.g. to get automatic updates from CDN again):

python3 download-offline.py --revert
python download-offline.py --revert
python3 download-offline.py --revert

This restores all HTML and TOML files to their original CDN URLs using the saved vendor/offline-manifest.json. The vendor/ folder itself is left in place — delete it manually if you want to reclaim the disk space.

✓ Completely self-contained

After running the download script once, the repo folder contains everything needed to run ObieWebApp. No internet, no browser cache, no external dependencies beyond Python 3 and Chrome/Edge.

To update to a new ObieApp version: git pull, re-run download-offline.py (it skips files it already has).

Run Explore.py (FRF viewer) and Aquire.py (impact-hammer acquisition) as native desktop applications — no browser, no server, no internet connection required after the initial install.

1
Install Python 3.10 or newer
One-time

The easiest way on macOS is Homebrew. If you don't have it:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Then install Python:

brew install python

Or download from python.org. Python 3.10–3.12 all work.

Download the installer from python.org. Choose Python 3.10, 3.11, or 3.12.

Important: On the first installer screen, check "Add Python to PATH" before clicking Install. 
python --version

Python 3 is usually pre-installed. Check:

python3 --version

If needed:

sudo apt update && sudo apt install python3 python3-pip python3-venv
2
Download the ObieApp code
One-time

Option A — Git clone (recommended, easiest to update later):

If you don't have Git: brew install git

If you don't have Git, download from git-scm.com and restart Command Prompt after installing.

If needed: sudo apt install git

git clone https://github.com/chrisbuerginrogers/ObieApp.git

Option B — ZIP download: go to github.com/chrisbuerginrogers/ObieApp, click Code → Download ZIP, then unzip anywhere.

The tools you'll run are inside Python/:

  • Python/Explore.py — FRF file viewer
  • Python/Aquire.py — Impact-hammer acquisition
3
Install Python packages
One-time 
cd ObieApp/Python
pip3 install numpy scipy matplotlib pyaudio
PyAudio on macOS: If it fails, first run brew install portaudio, then retry. 
cd ObieApp\Python
pip install numpy scipy matplotlib pyaudio
PyAudio on Windows: If it fails, try pip install pipwin && pipwin install pyaudio. 
cd ObieApp/Python
pip3 install numpy scipy matplotlib pyaudio
PyAudio on Linux: If it fails, first run sudo apt install portaudio19-dev python3-pyaudio, then retry.
All other modules (fileio, audioio, plotio, processing) are part of the repo — no extra installs needed.
4
Create a Data Folder and config file
One-time per setup

Both tools read a config.json from your Data Folder. The easiest way to create it is to use the web app to set up a Data Folder once — it creates ObieAppSettings/ with the right defaults — then copy that folder to your local machine.

Or copy the defaults from the repo:

cp -r "Python/ObieApp Settings" ~/Documents/MyObieData
xcopy /E /I "Python\ObieApp Settings" "%USERPROFILE%\Documents\MyObieData"
cp -r "Python/ObieApp Settings" ~/Documents/MyObieData

Edit the config.json inside that folder to set your instrument name and soundcard.

5
Run the tools
Every session

From the Python/ directory:

FRF viewer:

python3 Explore.py /path/to/MyObieData

Acquisition:

python3 Aquire.py /path/to/MyObieData

FRF viewer:

python Explore.py C:\Users\YourName\Documents\MyObieData

Acquisition:

python Aquire.py C:\Users\YourName\Documents\MyObieData

FRF viewer:

python3 Explore.py /path/to/MyObieData

Acquisition:

python3 Aquire.py /path/to/MyObieData

Both tools open a Matplotlib window and print status to the terminal.

✓ You're all set!

The desktop tools read and write the same .trf, .avc, and .avr files as the web app — your Data Folder works across both.
